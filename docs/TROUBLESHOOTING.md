# 常见问题

## 类目网址为什么去掉了 product-category

1.2.0采用类目根路径，旧址301到新址，内容不重建。按原文件夹更新、备份后正常停机重启即可迁移；启动提示根路径冲突时保留原拥有者，检查实际记录，不清空数据库。见[网址规则](URLS.md)。

## 输入内容后不能立即切换类目模板

这是防止ACF异步切换丢失未保存内容的保护。先Save Draft / Update，等待成功，再换模板并保存。提示期间原字段和输入仍在，不会自动发布或清空。原生预览继续支持未保存图文，分类身份保持原页关联。

## 同属类目页面，为什么显示不同样式

1.1.0 以前，同一个类目 CPT 的模板会根据有没有上级输出两套布局。现在打开对应内容页，在 Page Template → Template 查看实际选择：一级类目页｜系列总览，或二级类目页｜产品选型。两者可以用于任意层级，改上级不会自动换模板。旧名称分别是 Category: Overview 和 Category: Product selection；名称调整不改变布局或内容字段。完整操作见 [类目管理](CATEGORIES.md)。

旧副本升级前备份 `.runtime/`，更新源码后正常停机、重启。入口只执行一次布局选择迁移，保留已有页面外观和内容；之后不覆盖你选择的模板。不要重新导入种子或删除运行库。如果编辑页面仍显示旧选择，先刷新页面；旧编辑器有未保存内容时先保存或另行备份。

新建入口在 Products → Product Categories，可添加一级或子类并创建内容草稿。点击后已经有草稿或回收站页面时，应打开或恢复原页，不再另建一页。列表若显示 Conflict，先检查冲突内容；不要通过重置数据库绕过。

## 只有 Codex，没有 Node.js

让 Codex 执行项目的 `start.sh` 或 `start.ps1`。入口会检查现有 Node.js；版本不合适时下载 Node.js 22.20.0 到 `.tools/`，校验官方发行文件指纹。不会全局安装或改系统设置。首次下载需要联网。

## 端口被占用

使用 `bash start.sh --port 9401`，或 `npm start -- --port 9401`。Windows 使用 `./start.ps1 --port 9401`。不要为此终止其他项目的进程。

## 提示这个副本已经运行

先打开终端给出的原地址。若要重新启动，先在原终端按 Ctrl+C。运行锁用于阻止两个进程同时写同一份数据库；程序会自行识别已经退出的旧进程。不要在另一个进程仍运行时删锁。

## 首次依赖下载失败

检查到 npm registry、nodejs.org 的网络访问，恢复后重复运行启动入口。不要把不明来源的镜像压缩包替换进 `packages/`。包校验失败时重新下载仓库对应文件，保留自己的 `.runtime/`。

## 修改了内容，重新下载后不见了

GitHub 保存的是初始演示。你后来的 CMS 修改在原文件夹的 `.runtime/`；用同一个文件夹启动，或按 [数据说明](DATA.md) 迁移自己的运行目录。

## ACF 更新或授权提示

演示不附带原作者的许可证。现有字段内容可以编辑；官方更新、支持和受授权限制的新字段组功能使用自己的许可证。不要填写或索要原作者密钥。

## 表单没有收到邮件

这是演示的预期行为。到 Fluent Forms → Entries 查看本地记录。仓库没有企业邮箱配置，启动不需要 SMTP 或 Hostinger 账号。

## 初次运行有默认欢迎内容或字段缺失

先等待终端打印 Website 和 CMS 地址。初始化失败时保留错误信息，让 Codex 检查实际阶段；不要反复创建另一个 WordPress 或覆盖已修改的数据库。检查包完整性后，可在单独的新克隆目录验证初始站点。

## 旧副本出现间歇 500 或草稿预览缺正文

1.0.2 修复了本地前后台重叠请求、缺少 ACF 快照的已保存草稿预览，以及换端口后的后台提示链接。获取最新版源码后，正常停止并重新启动此副本，保留整个 `.runtime/`。不要删除数据库或重新导入初始内容。更新前先备份自己的运行数据，详见 DATA.md。

## 已登录后台，前台没有顶部编辑工具栏

1.0.3 已恢复专用演示账号的默认前台工具栏，并补齐原生资料保存所需的昵称。旧副本更新源码后，正常停止并重启；升级只修复一次默认值，不重新导入内容。之后你在“用户 → 个人资料”修改的工具栏开关会保留。

前台和后台需在同一浏览器，并使用启动入口打印的同一地址；不要混用 localhost、127.0.0.1 或不同端口。仍未显示时，到“用户 → 个人资料”勾选“Show Toolbar when viewing site”，点击“Update Profile”，等待“Profile updated.”后刷新前台。

1.0.3 同时去除了导航选中项的黄色下划线，并统一了前台询盘下拉箭头的右侧 16px 留白。键盘焦点提示保留；这不会改变表单选项或已保存内容。

## 额外 npm audit 遇到镜像 404

这与网站启动或 `npm run audit:package` 的文件完整性检查不同。部分 npm 镜像没有安全审计 API，可仅为这次额外检查运行 `npm audit --registry=https://registry.npmjs.org`，无需改全局 npm 设置。结果是当次依赖锁和当时公告的检查，不是长期无漏洞保证。
